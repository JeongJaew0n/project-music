## 결정

- **새 FeatureGroup `songcut/`.** 받기(ytmp3)와 하는 일이 다르다. 이름을 `clip` 으로 하지 않은
  이유: OpenAI CLIP 같은 AI 패키지가 최상위 `clip` 을 쓴다. 이 프로젝트는 곧 AI 패키지를 들인다.
- **경로를 공용 `shared/paths.py` 로 옮긴다.** `ytmp3/paths.py` 에 "다른 FeatureGroup 이 생기면
  옮긴다"고 적어 뒀다. 최상위 이름을 `studio` 로 하지 않은 이유: 데이터 폴더 `studio/` 와 겹친다.
- **잘라낸 곡은 `studio/works/cuts/`.** 작업 결과 안에서도 작업 종류별로 나눈다(사용자가 2026-11-14 에
  "구분해서 저장"을 요청).
- **다시 인코딩한다.** mp3 를 그대로 복사해 자르면 프레임(약 26ms) 경계에서만 잘리고, 비트 저장소
  때문에 첫 프레임이 깨질 수 있다. 디코딩 → 자르기 → V0 로 다시 인코딩하면 원하는 지점에서 정확히
  잘리고 페이드도 넣을 수 있다. V0 재인코딩 손실은 들리지 않는 수준.
- **AI 가 쓰는 길: 명령줄 `songcut` + `--json`.** AI 는 들을 수 없으니 `songcut info` 가
  초 단위 소리 크기(dBFS)와 조용한 구간을 숫자로 준다 — 어디를 자를지 고를 근거.
  같은 분석에서 화면의 파형도 뽑는다.
- **사람이 쓰는 길: 기존 웹 화면(ytmp3-web)에 붙인다.** 홈 화면에 이미 올라간 앱이 하나라
  거기서 받고 바로 자르는 게 자연스럽다. 웹 서버를 따로 띄우면 LaunchAgent·proxy 가 하나 더 는다.
- 시간 표기는 `83`, `83.5`, `1:23`, `1:23.5`, `0:01:23` 을 받는다. 끝은 음수면 곡 끝에서 거꾸로
  (`-10` = 끝나기 10초 전). 끝이 곡 길이를 넘으면 곡 끝으로 맞춘다. 시작이 곡 길이 이상이면 실패.
- 같은 이름의 결과가 있으면 덮어쓰지 않고 ` (2)` 를 붙인다.
- 경계 딸깍 소리를 막는 짧은 페이드는 기본으로 넣지 않는다 — 사용자가 정확한 지점을 원할 수 있다.
  `--fade-in`·`--fade-out` 으로 준다.

## 기각

- 브라우저에서 WebAudio 로 전체 디코딩해 파형 그리기 — 4분 곡이면 메모리 80MB 남짓, 폰에서 무겁다.
  서버가 8kHz 모노로 디코딩해 수백 개 값만 보낸다.
- numpy 의존성 — 8kHz 모노 4분 곡이 약 200만 샘플이라 순수 파이썬으로도 1초 안쪽.
